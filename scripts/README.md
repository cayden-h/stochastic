# scripts

Helper scripts. Owner: Eric (data pulls) and Cayden (agent probes).

| Script | What it does |
| --- | --- |
| `fetch_filings.py` | Downloads the five Kewaunee and Nu Aire filings from EDGAR into `data/raw/` (git-ignored) with a plain-text copy of each. Needs `SEC_USER_AGENT` in `.env`. |
| `load_lines.py` | Not the loader the API uses: `POST /deals` parses uploads with the strict `backend/app/db/loader.py`, and the statement CSV this script writes is accepted there (extra columns such as `company` and `note` are ignored). `export` writes the fixture to `data/kewaunee_lines.csv` and `data/nuaire_lines.csv`; `check` reloads them and compares with the fixture. `load_lines()` turns one CSV into `SourceLine` rows for the fixture and `POST /deals`. It also reads a QuickBooks Online trial balance (.xlsx, or the same rows as CSV) with the Account List export for account types, and derives net income, the balance sheet totals, D&A, interest, and income taxes. Numbered accounts work without the list. It also has layout profiles for NetSuite, Sage Intacct, Microsoft Dynamics 365 (Business Central and Finance), Epicor, and Infor. Those five are unverified: they were written from how those reports are usually laid out, never run on a real export, and every line they load says "(layout unverified)" in its source. `tb <trial balance> [<account list>]` prints what it loads. This path is not part of the demo and adds no backend dependency: .xlsx is read only where `openpyxl` happens to be installed, and otherwise the export is saved as CSV first. The two tests on the real .xlsx exports skip without `openpyxl`. |
| `test_load_lines.py` | Loader tests: `backend/.venv/bin/python -m pytest -q scripts/test_load_lines.py`. The QuickBooks tests use real exports. The tests for the five unverified layouts use small files we wrote ourselves, so they show the code runs, not that real exports load. |
| `samples/qbo/trial_balance.xlsx`, `samples/qbo/account_list.xlsx` | Real, unedited exports from the QuickBooks Online test-drive demo company (Craig's Design and Landscaping Services, public sample data), downloaded 2026-10-24. The loaded totals match that company's own Balance Sheet report for the same date. On 2026-10-24 the whole deal ran with this file as the target (Kewaunee from the fixture, scripted backend): tie-out passed, the Reviewer passed, and the Mapper raised 40 flags, because the scripted Mapper only knows the demo deal's line names. |
| `samples/qbo/nuaire_trial_balance.csv`, `samples/qbo/nuaire_account_list.csv` | Nu Aire's audited statement lines (Ex 99.1) laid out in the same QuickBooks layout. We chose the account types and detail types, and retained earnings is set before close (ending balance less the year's net income). Not a real Nu Aire export: account-level detail is not public. |
| `droid_rewind_probe.py` | Probes `Session.rewind` with two codewords: after rewinding to the second turn's prompt, the successor session keeps the first codeword only. Spends a few Factory credits. |
| `droid_rewind_live_check.py` | Runs the demo deal on Droid, forces the gateway to refuse the Mapper's result, and checks Factory's session records: the old session holds the refused turn, the successor the retry uses does not. Spends Factory credits. |
| `droid_rewind_api_check.py` | End-to-end check through the real API server on Droid with the demo's models: a forced refusal, the rewind, the whole deal through approval, then a second deal that resumes the successor session, and Factory's session records. 20 checks; passed on 2026-10-24. Spends Factory credits. |
| `droid_probe.py` | Lists the models our Factory key can run and makes one `run()` call with structured output in an empty directory. Answers "can Droid run Claude?" |
| `record_run.py` | Runs the whole deal on a chosen backend and saves each agent's output to `backend/recordings/`, the replay fallback for the demo. |
| `run_unseen_deal.py` | Runs the whole deal with a QuickBooks trial balance as the target, in memory, on `AGENT_BACKEND`, and prints the flags, mappings and verdict. For a judge's own scenario. The live Droid run on the sample company is in `evals/unseen-input-quickbooks.md`. |
