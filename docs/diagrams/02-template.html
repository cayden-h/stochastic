WHEN THINGS CHANGE

Three loops that run inside the deal: an event, a blocked plan, and a rejection

A

AN EVENT ARRIVES

The deal does not restart. Only the stale parts run again.

EventRate move, lender change, or a late document.
Gateway logs itThe event becomes a work item with a time stamp.
Deal managerMarks every affected result stale.
Re-runOnly stale steps run again: deal math, Monte Carlo.
Did the best plan change?If no, the memo updates and the deal goes on.
E5ReviewerSees what changed and why before anything moves on.
B

A CLAUSE BLOCKS THE PLAN

This is the demo moment. The block is a logged action, not a sentence in a report.

Structuring agentProposes the best plan it found.
Deal mathChecks the plan against each limit. One clause fails.
GatewayLogs a DENIED transition. It cites the exact clause quote.
Redesign and priceNew plan inside the limit, plus the cost of asking the lender for consent.
E4ReviewerSees both routes with the evidence, then chooses.
C

A REJECTION BECOMES A POLICY

The system gets better from a "no". It needs a few seeded past decisions for evidence.

E6Reviewer rejectsGives a reason in plain words.
Memo agentSearches past decisions for the same pattern.
Proposes a policyA general rule, with the evidence behind it.
BacktestRuns the rule on past deals to see what it would change.
Senior approvesA human approves the policy. The agent that wrote it cannot.
Policy savedThe next deal starts with this rule.
