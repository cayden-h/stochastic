THE SIX AGENTS

Each agent has one job, a clear input and output, a point where it asks the human, and one thing it never does

Deal manager

decides who asks
Runs the deal. The master agent.
GETS
The one-line brief and every event.
MAKES
Situation type (1 of 8), playbook, task list, stale marks.
ASKS
When two results disagree, or a task cannot finish.
NEVER
Does the math, or writes a record directly.

Intake agent

E1E2
Reads the documents.
GETS
Uploaded or cached documents.
MAKES
A fact table: value, page, quote. A list of missing documents.
ASKS
E1 for a missing document. E2 to confirm the facts the plan relies on.
NEVER
Guesses a missing number.

Clause reader

E3
Finds the limits in the loan agreement.
GETS
The agreement text and the fact table.
MAKES
Constraints: clause, exact quote, plain meaning, confidence, defined terms.
ASKS
E3 when a quote or a defined term is unclear.
NEVER
Keeps a quote that the validator cannot find in the document.

Structuring agent

E4
Designs the financing mixes.
GETS
Constraints, target amount, and the objective weights of the situation profile.
MAKES
Candidate mixes of senior, junior, and preferred. A shortlist. A blocked-plan record with the clause and a consent route.
ASKS
E4 when a clause blocks the plan.
NEVER
Invents terms or computes numbers itself. It calls the math tools.

Risk agent

E5
Tests each plan under many futures.
GETS
The shortlist and labeled assumptions (rates, growth, volatility).
MAKES
Monte Carlo results with a run id: odds of a covenant breach, a blocked dividend, a loss.
ASKS
E5 when an event flips the best plan.
NEVER
Reports a number without a seed and a run id.

Memo and approvals agent

E6
Writes it up and learns from a "no".
GETS
All results, with their citations and run ids.
MAKES
The recommendation, the side-by-side table, and a policy proposal after a rejection.
ASKS
E6 for the final decision.
NEVER
Approves its own work or its own policy.

SIX RULES THE GATEWAY ENFORCES

  1. Only the gateway posts to the record.
  2. The proposer of an item cannot approve it.
  3. An agent can call only the tools it was given.
  4. Every number carries a run id from the math code.
  5. A reversal is a new item linked to the original. Nothing is deleted.
  6. Every action and every denied attempt goes in the log. Each log row is chained to the one before.

DENIED: THE ACTION IS NOT APPLIED

Any forbidden action is refused and written to the log. Examples: an agent approves its own item, calls a tool it was not given, or posts a number with no run id. A denied attempt is evidence, so it is kept.

Why this matters: the Hyphenate workshop calls this the system of work. Records hold the truth. The system of work holds the tasks, the decisions, the questions, and the log.
